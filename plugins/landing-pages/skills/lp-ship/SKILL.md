# lp-ship: פרסום הדף לאוויר

## 1. חוקי ההבטחה (מחייבים)

- **אין שאלות באמצע.** שם הפרויקט, התיקייה והיעד נגזרים לבד לפי סעיף 3. לא שואלים "לאיזה שם לפרסם".
- **אין עצירות אישור.** עצירה לאישור היא ברירת מחדל כבויה, ונדלקת רק אם המשתמש אמר במפורש שהוא רוצה לאשר בדרך.
- **דרישת קדם חסרה לא מפילה כלום.** CLI לא מותקן, אין חיבור, אין רשת: מדווחים בעברית בשורה או שתיים, מציעים חלופה, וממשיכים עם מה שאפשר.
- **לא מכריזים "באוויר" בלי אימות.** הכרזה מותרת רק אחרי שהבדיקות בסעיף 6 חזרו כמצופה.
- לא ממציאים כתובת. אם הפרסום לא הצליח, אומרים את זה ונותנים את הנתיב המקומי.

## 2. שלב 0: טרום פרסום

```bash
DIR="$(pwd)"
ls -la "$DIR"/index.html "$DIR"/legal.html "$DIR"/404.html
```

| בדיקה | פקודה | למה |
|---|---|---|
| שלושת הדפים קיימים | `ls index.html legal.html 404.html` | דף בלי `legal.html` ובלי `404.html` לא נמסר. אם חסר, מריצים קודם את `lp-legal` |
| אין נתיבים מקומיים שדלפו | `grep -n 'file:///\|/Users/' index.html legal.html 404.html` | נתיב מקומי עובד אצלך ושבור לכולם. חייב לחזור ריק |
| כל נכס קיים בפועל | `grep -o 'src="[^"]*"' index.html \| sed 's/src="//;s/"//' \| while read f; do [ -f "$f" ] \|\| echo "חסר: $f"; done` | תמונה חסרה מגיעה לאוויר כריבוע שבור |
| השער עבר | הפלט של `lp-qa` | אם השער לא רץ בסשן הזה, מריצים אותו עכשיו |

**אם השער מחזיר FAIL על תקלה חוסמת** (גלישה אופקית, תמונה בגובה 0, תוכן חתוך, כפתור מתחת ל-44px): מתקנים לפי `lp-qa` ואז מפרסמים. לא מחכים לאישור ולא מפרסמים דף שבור.

## 3. גזירת השם והכתובת

הכתובת הנקייה היא `<slug>.vercel.app`. גוזרים את ה-slug בסדר הזה, בלי לשאול:

1. שם התיקייה, אם הוא באותיות לטיניות: `basename "$DIR"` אחרי המרה לאותיות קטנות והחלפת כל תו שאינו אות, ספרה או מקף במקף.
2. אחרת, שם הדומיין של העסק מהבריף בלי הסיומת (למשל `focus-sales.co.il` הופך ל-`focus-sales`).
3. אחרת `landing-<YYYYMMDD>`.

```bash
SLUG="$(basename "$DIR" | tr '[:upper:]' '[:lower:]' | sed 's/[^a-z0-9-]/-/g; s/--*/-/g; s/^-//; s/-$//')"
case "$SLUG" in ""|*[!a-z0-9-]*) SLUG="landing-$(date +%Y%m%d)";; esac
echo "$SLUG"
```

בסיכום כותבים את הכתובת שנבחרה ואומרים שאפשר לשנות אותה בלוח הבקרה של וורסל. לא שואלים מראש.

## 4. שלב 1: `.vercelignore` לפני הדיפלוי

חייב להיכתב **לפני** הפקודה, אחרת חומרי עבודה עולים לאוויר והדיפלוי מתנפח:

```bash
cat > "$DIR/.vercelignore" <<'IGNORE'
qa
node_modules
assets/src
assets/src-old
assets/src-drive
_orig-*.html
*.bak
*.bak-*
brief.md
copy.md
docs
IGNORE
```

בנוסף `vercel.json` שנותן כתובות נקיות ומטמון נכון:

```json
{
  "cleanUrls": true,
  "trailingSlash": false,
  "headers": [
    { "source": "/assets/(.*)", "headers": [ { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" } ] },
    { "source": "/(.*)\\.html", "headers": [ { "key": "Cache-Control", "value": "public, max-age=0, must-revalidate" } ] }
  ]
}
```

`cleanUrls` הוא מה שמאפשר `/legal` בלי `.html`. הקישורים בפוטר יכולים להישאר `legal.html`, שניהם יעבדו.

## 5. שלב 2: הדיפלוי וה-alias

```bash
cd "$DIR"
vercel whoami || echo "לא מחובר"
vercel deploy --prod --yes --name "$SLUG" 2>&1 | tee /tmp/lp-deploy.log
DEP="$(grep -oE 'https://[a-z0-9.-]+\.vercel\.app' /tmp/lp-deploy.log | tail -1)"
echo "deployment: $DEP"
vercel alias set "$DEP" "$SLUG.vercel.app"
```

נקודות שחוסכות זמן:

- **שתי פקודות, לא אחת.** הדיפלוי מחזיר כתובת ארוכה עם גיבוב. שלב ה-`alias` הוא מה שנותן את הכתובת הנקייה, וזו הכתובת שמוסרים.
- `--name` עדיין מתקבל אבל מסומן כמיושן בגרסאות CLI חדשות, ושם הפרויקט בפועל נגזר משם התיקייה. אם השם יוצא אחר ממה שביקשת, זה הסבר: מריצים מתיקייה בשם ה-slug, או `vercel link --yes --project "$SLUG"` לפני הדיפלוי.
- דיפלוי ראשון מתיקייה חדשה יוצר פרויקט חדש בחשבון המחובר. `--yes` מאשר את כל ברירות המחדל בלי שאלות, וזה בדיוק מה שצריך כאן.
- ה-alias מתפשט תוך שניות. אם האימות נכשל בניסיון הראשון, מנסים שוב עד שלוש פעמים עם המתנה קצרה, ורק אחר כך מכריזים על כשל.

## 6. שלב 3: אימות אחרי הפרסום (חובה)

```bash
U="https://$SLUG.vercel.app"
for i in 1 2 3; do
  I="$(curl -sS -o /dev/null -w '%{http_code}' "$U/")"
  L="$(curl -sS -o /dev/null -w '%{http_code}' "$U/legal")"
  [ "$L" = "200" ] || L="$(curl -sS -o /dev/null -w '%{http_code}' "$U/legal.html")"
  E="$(curl -sS -o /dev/null -w '%{http_code}' "$U/ein-kaze-daf-123")"
  B="$(curl -sS -o /dev/null -D - -H 'Accept-Encoding: br' "$U/" | grep -i '^content-encoding' | tr -d '\r')"
  echo "index=$I legal=$L 404=$E $B"
  [ "$I" = "200" ] && [ "$L" = "200" ] && [ "$E" = "404" ] && break
  sleep 4
done
```

**מה חייב לחזור:** `index=200`, `legal=200`, `404=404`, ו-`content-encoding: br`.

- `404=200` פירושו שוורסל מגיש את הדף הראשי לכל נתיב. בודקים ש-`404.html` יושב בשורש התיקייה ולא בתוך תת תיקייה.
- אין `content-encoding: br` פירושו שהתגובה לא נדחסה. בודקים ש-`curl` באמת שלח `Accept-Encoding: br`, ואם כן, זה מקרה שראוי לדווח עליו בסיכום.
- אצל וורסל `curl` מספיק לאימות. לרב מסר הוא לא מספיק, סעיף 8.
- אחרי ה-`curl` פותחים את הכתובת בכרום אמיתי, מסתכלים במובייל ובדסקטופ, ובודקים שאין שגיאות בקונסולה, שהתמונות נטענו ושהטופס מוצג.

## 7. שלב 4: כשה-CLI לא מותקן או לא מחובר

**לא נופלים, לא מחכים.** מזהים ומסבירים:

```bash
command -v vercel >/dev/null || echo "אין CLI"
vercel whoami 2>&1 | head -2
```

הנוסח למשתמש, בעברית פשוטה:

> ה-CLI של וורסל לא מותקן. שתי פקודות בטרמינל וזה מסודר:
> `npm i -g vercel`
> `vercel login`
> ההתחברות פותחת לך חלון בדפדפן ומבקשת אישור. אחרי שאישרת, תגיד לי ואני מפרסם.

שתי חלופות שממשיכות גם בלי CLI, ומציעים אותן מיד באותה הודעה:

1. **הדף עדיין אמיתי מקומית.** פותחים את `index.html` בדפדפן ורואים בדיוק את מה שיעלה לאוויר. אפשר גם להעלות את התיקייה בגרירה ללוח הבקרה של וורסל בדפדפן.
2. **רב מסר**, אם יש חיבור, סעיף 8.

`vercel login` הוא אינטראקטיבי ודורש דפדפן, ולכן הוא **לא מורץ אוטומטית** ולא ממתינים לו בתוך הצינור. מדווחים וממשיכים.

## 8. חלופת רב מסר (ravpage)

כשוורסל לא זמין או שהלקוח דורש שהדף יישב אצלו במערכת הדיוור.

### 8.1 סדר הפעולות

1. **`get_account` קודם כל.** מוודאים שה-Connector מחובר לחשבון הנכון. חשבון שגוי פירושו דף שמתפרסם אצל לקוח אחר.
2. `list_landing_pages` מחזיר תשובה ענקית. קוראים אותה עם `jq` מקובץ תוצאות הכלי ושולפים את `publish_domains`.
3. **מפצלים את הדף לשלושה שדות:**
   - `html`: הגוף בלבד, בלי `<head>`, בלי `<style>` ובלי `<script>` שלך.
   - `css`: הגיליון המלא, ממוזער. **מטמיעים אותו מלא** ולא מקשרים אליו, כדי שהדף לא יישאר בלי עיצוב אם האירוח החיצוני ייפול.
   - `js`: עטוף ב-`DOMContentLoaded`, כי סדר ההזרקה לא מובטח.
4. **כל הנתיבים אבסולוטיים.** תמונות, `legal`, `404`. נתיב יחסי נשבר בתוך הדומיין של רב מסר.
5. **עוטפים את כל ה-HTML ב-`<main>` ומתחמים את כללי ה-CSS** (`main h2`, `main p{margin:0}`). לרב מסר יש reset משלהם שמתנגש, והם גם טוענים גיליון חיצוני מ-`css.ravpages.co.il` עם `!important`. סלקטורים של class לא מנצחים אותו, אז מה שחייב לנצח נכתב עם **סלקטור מבוסס ID** (`#rmLive input{...!important}`).
6. **`upload_image` של רב מסר מחזיר null ולא עובד.** הנכסים מתארחים בוורסל ומקושרים משם בכתובת מלאה. אם אין וורסל, כל אירוח סטטי אחר של הלקוח.
7. **`upsert_landing_page` אסינכרוני.** לוקחים את ה-`tool_call_id` מהתשובה ובודקים `get_async_tool_call_status` שוב ושוב עד `completed`. תשובה ראשונה אינה סיום, ולא מפרסמים לפניה.
8. `publish_landing_page` עם כתובת **על הדומיין של החשבון בלבד**, מתוך `publish_domains` שנשלף בשלב 2.
9. שדה ה-`title` ב-`upsert` הוא שם פנימי לרשימת הדפים, **לא** ה-`<title>` של הדף.

### 8.2 אימות רב מסר

**בכרום אמיתי, לא ב-curl.** Cloudflare של ravpage חוסם `curl` ו-Playwright headless, ושניהם יראו "הדף לא נטען" או "הטופס לא נטען" גם כשהכול תקין. `file://` נחסם בנוסף ב-CORS.

מה בודקים בכרום: תמונות שבורות, הטופס נטען ונשלח בפועל, ה-CSS הוחל, הפיקסל יורה, ואין גלישה אופקית בדסקטופ ובמובייל.

**שליחת טופס נחשבת תקינה רק כשרואים** בקשת POST ל-`safe-subscriber.responder.live`, ואחריה ניווט ל-`secure.cardcom.solutions/.../PaymentSP` כשיש סליקה. אם ברשימת הבקשות אין POST בכלל, הטופס לא נשלח, גם אם הוא נראה מושלם.

## 9. הפלט למשתמש

עברית פשוטה, בלי מקפים ארוכים:

```
הדף באוויר: https://focus-sales.vercel.app

אומת:
- דף הבית מחזיר 200
- הדף המשפטי מחזיר 200
- נתיב שגוי מחזיר 404 ומגיש את דף השגיאה שלך
- התגובה נדחסת (brotli)

מה נשאר לך:
- מזהה הפיקסל של מטא, כרגע [למלא] בקובץ
- ח.פ. ומייל בפוטר ובתקנון, כרגע [למלא]
- טקסט הכפתור בטופס מוגדר במערכת הדיוור, לא בדף
- אימות הדומיין במטא, אם תריץ ממומן לכתובת הזאת
```

בכשל, במקום כתובת:

```
הפרסום לא יצא לדרך: <מה בדיוק נכשל>
הדף מוכן ועובד מקומית: /נתיב/מלא/index.html
כדי לפרסם: npm i -g vercel ואחר כך vercel login, ואז תגיד לי ואני מעלה.
```

## 10. מה אסור

- לא מפרסמים דף עם `[למלא]` **במקום שהמבקר רואה** בלי לאמר את זה בסיכום. בפוטר או בתקנון זה מקובל ומדווח, בכותרת ההירו זה לא מתפרסם.
- לא ממציאים ח.פ., מייל, כתובת או טלפון כדי ש"הפוטר ייראה שלם".
- לא מפרסמים נכסים של לקוח אחר שנשארו בתיקייה. בודקים את `.vercelignore` ואת תיקיית `assets`.
- לא מפרסמים לדומיין של לקוח בלי שהוא ביקש. ברירת המחדל היא תמיד `<slug>.vercel.app`.
